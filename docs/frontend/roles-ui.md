# Роли и интерфейс

Роль и права берутся из `GET /api/v1/home`: поля `role`, `permissions`, `bank_role`. Код проверки лежит в `frontend/src/app/access.ts`.

## Три уровня проверки

1. **Роут.** Страница, недоступная роли, показывает экран «Недостаточно прав» с подсказкой, кто может выполнить действие. Форма при этом не открывается. Компонент `features/profile/components/RequireAccess.tsx`.
2. **Блок на странице.** Например, бухгалтер видит на главной плашку «Подбор и подача заявок недоступны» вместо кнопок подбора.
3. **Кнопка действия над заявкой.** Кнопка показывается только по `available_actions` из ответа бэка. Если действие недоступно роли, вместо кнопки строка с объяснением, например «Решение принимает собственник или директор».

Если у пользователя `role = null`, весь кабинет закрыт экраном «Нет доступа к компании».

## Права по умолчанию (К.5)

Если бэк прислал `permissions`, главнее они. Если массив пустой, используется эта таблица.

| Роль | Подбор и подача | Документы | Подпись | Решение по предложению | Команда |
|---|---|---|---|---|---|
| owner | да | да | по правилам подписи | да | да |
| director | да | да | да | да | нет |
| cfo_or_accountant | нет | да | по правилам подписи | нет | нет |
| financing_employee | да | да | нет | нет | нет |
| banking_employee | да | да | нет | нет | нет |
| authorized_employee | нет | да | по доверенности | нет | нет |

## Какие роуты закрыты

| Роут | Нужное право |
|---|---|
| `/match/...`, `/products`, `/products/:code` | `submit_applications` |
| `/team/invite` | `manage_team` |
| `/applications/:id/edit` | `application.edit` в `available_actions`, иначе переход на карточку |
| `/bank/...` | `bank_role` |

Главная выбирается по `home_profile`: `entrepreneur` → S5, `accountant` → S6.
