# Открытые вопросы к контрактам

Фронтенд сделан строго по разделу «Контракты API» в `FRONTEND_SPEC.md`. Ниже места, где контракта не хватило. В каждом пункте указано, какая заглушка сейчас стоит в интерфейсе.

| # | Где | Вопрос | Как сделано сейчас |
|---|-----|--------|--------------------|
| 1 | S9-S11 | Нет `GET /matching-sessions/{id}`. Без него после перезагрузки страницы шаг подбора не восстановить | Пустой `PATCH /matching-sessions/{id}` с телом `{}` возвращает текущую сессию. Бэк не должен менять `updated_at` на пустом PATCH |
| 2 | S14 | У действия `pick_document` нет ручки, которая прикрепляет выбранный документ к заявке | Выбор сохраняется в `form.data.picked_<code>` через `PATCH /applications/{id}` |
| 3 | S17 | «Отказаться» ведёт на S12 «с альтернативами», но в заявке нет `matching_session_id` | Создаётся новая сессия, ответы берутся из заявки: цель, сумма, срок |
| 4 | S4 | По спецификации «ФИО, роль и логин показываются после проверки кода», но отдельной ручки проверки кода нет | Логин показывается после `POST /auth/invite/accept` |
| 5 | S20 | Тип документа определяет ИИ, «пользователь подтверждает», но ручки подтверждения типа нет | Показываем определённый тип. Если он неверный, файл заменяют через «Заменить» |
| 6 | S20 | «История версий» есть в макете, но в `DocumentRef` только номер текущей версии | Показываем номер версии и пометку «прошлые версии заменены» |
| 7 | B3 | Формат `GET /bank/info-request-templates` и `GET /bank/rejection-reasons` не описан | `{ code, title, question, requested_document_types }[]` и `{ code, title }[]`, см. `src/api/types.ts` |
| 8 | B4 | Формат `GET /bank/settings/scoring` не описан | Отдаётся `ScoringThresholds` |
| 9 | К.2 | Вход по почте: в теле `POST /auth/login` поле по-прежнему называется `login`, в нём передаётся почта | Поле «Почта», проверка на символ @ |
| 10 | К.5 | Где проверяется `company.edit_details` для S10 «Изменить»: в `FinanceSummary` нет `available_actions` | По роли: owner, director, cfo_or_accountant, как в таблице К.4 |
