# Скоринг, нагрузка и подбор: допущения команды

Кредитное решение принимают детерминированные правила и аналитик. LLM в расчётах не участвует: числа, баллы и `outcome` считает код (`backend/app/domain`). Ниже параметры, которые команда приняла сама: их нет в публичных материалах банка.

## Нагрузка (3.1)

| Параметр | Значение | Где менять |
|---|---|---|
| Ставка прототипа | 15% (`RATE_PERCENT_DEFAULT`), в подборе ставка продукта `rate_from_percent` | `.env`, `app/domain/catalog.py` |
| Порог нагрузки | 30% (`LOAD_THRESHOLD_PERCENT`) | `.env` или B4 «Настройки скоринга» |
| Целевая нагрузка для рекомендаций и контрпредложений | 26,5% (`LOAD_TARGET_PERCENT`), запас от порога | `.env` или B4 |

- Период: последние 12 полных месяцев операций из Альфа-Бизнеса (мок). Без переводов между своими счетами, поступлений кредитов и платежей по кредитам.
- Платёж: аннуитет `S × r / (1 - (1 + r)^-n)`, `r = rate / 12 / 100`. Округление до целого рубля по математическим правилам: так совпадает контрольный пример ТЗ (96 973 ₽ для 2 000 000 ₽ на 24 мес; при округлении вверх получилось бы 96 974 ₽).
- Нагрузка `(новый платёж + текущие платежи) / свободный поток × 100`, один знак после запятой.
- Овердрафт гасится поступлениями, поэтому в нагрузку идут только проценты за месяц на весь лимит. Лимит овердрафта: 45% средних поступлений, вниз до 100 000 ₽.
- Свободный поток не больше нуля: нагрузка не считается (в ответе 999,9%), стоп-фактор «Расходы не меньше поступлений».

## Скоринг (3.5)

| Фактор | Максимум | Правило |
|---|---|---|
| Срок бизнеса | 20 | ≥ 36 мес: 20; 12-35: 14; 6-11: 8; < 6: 0 |
| Кредитная история | 20 | без просрочек: 20; просрочки до 30 дней за 12 мес: 10; хуже: 0 |
| Нагрузка | 25 | ≤ 20%: 25; ≤ 25%: 18; ≤ 30%: 10; > 30%: 0 |
| Отрасль | 15 | справочник по префиксу ОКВЭД: 25.62 → 9, 62 → 12, 47 → 10, 56 → 8, прочие 8 |
| Обороты | 20 | 20 минус 8 за месяц без поступлений и минус 3,5 за месяц спада (поступления ниже 80% среднего); меньше 6 месяцев истории: 0 |

Пороги: одобрение ≥ 70, другие условия 55-69, ручная проверка 45-54, отказ < 45. Стоп-факторы дают отказ без балла: компания не действует, текущая просрочка в БКИ, налоговый долг больше 10 000 ₽, бизнесу меньше 3 месяцев, свободный поток ≤ 0.

Демо: 2 000 000 ₽ на 24 мес дают 20 + 20 + 0 + 9 + 13 = 62 (в очередь аналитика с рекомендацией «другие условия»); 1 500 000 ₽ на 36 мес: нагрузка 26,2%, 10 баллов за нагрузку, итого 72 и авторешение.

## Авторешение после отправки

1. Автопроверки по мокам (реестр, БКИ, обороты, ФНС, нагрузка). Мок не ответил: проверка `error`, заявка остаётся аналитику.
2. Не хватает обязательного документа: система создаёт запрос информации.
3. Стоп-фактор или балл < 45: отказ.
4. Балл ≥ 70 и нет предупреждений: одобрение (`decided_by = auto`).
5. Иначе очередь аналитика, `outcome` как рекомендация.

Сезонный спад поступлений не считается предупреждением: в демо он есть у ООО «Машпромхоз» каждый январь и февраль. Предупреждение даёт месяц совсем без поступлений.

## Подбор (3.2)

- Сроки перебираются из `{запрошенный, запрошенный + 12}` в пределах продукта, суммы от запрошенной вниз шагом 100 000 ₽. Берётся максимальная сумма с нагрузкой ≤ целевой, при равенстве короче срок.
- Главная рекомендация: продукт с наибольшей подобранной суммой; при равенстве меньше переплата или по `preference` клиента.
- `fit = high`, если нагрузка ≤ целевой и все пункты готовности, кроме документов и нагрузки, в статусе `ok` (нагрузка оценивается отдельно для каждого варианта).
- Если по ответам клиента не подошёл ни один продукт, подбор смотрит все продукты, доступные по форме бизнеса, сроку работы и залогу.

## Контрпредложение (3.6)

Тот же перебор для продукта заявки и других продуктов под ту же цель на сроках запрошенный, +12, +24. Варианты с нагрузкой ≤ целевой и баллом ≥ 70, до трёх, по убыванию суммы.
