# Тестовые сценарии

Три уровня проверки:

1. **Ручные E2E-сценарии в интерфейсе** (ниже): то, что эксперт проходит руками на http://localhost:8080.
2. **Postman-коллекция** [../postman/BlokTea.postman_collection.json](../postman/BlokTea.postman_collection.json): те же сценарии через API, запуск целиком в Collection Runner.
3. **Автотесты**: pytest на бэкенде и Vitest на фронтенде, запускаются в CI.

Перед каждым прогоном сбросьте демо-данные: `make reset-demo`. Пароль всех демо-учёток `alfa2026`. Код подтверждения показывается рядом с полем ввода (`DEMO_MODE=true`).

## Postman

| Папка | Что проверяет |
|---|---|
| 1-6 | health, вход, ротация и отзыв refresh-токенов, выход, пользователь без роли |
| 7-8 | главная и список заявок: контракт, фильтры, сортировка, пагинация, ошибки |
| 9 | лента для ООО и ИП различается, у каждой новости есть причина показа |
| 10 | TC-03: авторешение |
| 11 | TC-04 через API: запрос информации, выписка из Альфа-Бизнеса, ответ |
| 12 | TC-05: отказ с объяснением |
| 13 | TC-02: контрпредложение, два подписанта, выдача и график |

Папка 13 выдаёт кредит и меняет нагрузку компании, поэтому она идёт последней, а перед повторным прогоном нужен `make reset-demo`.

## Автотесты

| Набор | Где | Что покрывает | Запуск |
|---|---|---|---|
| unit (189) | `backend/tests/unit` | скоринг, нагрузка, подбор, переходы статусов, LLM-клиент, безопасность | `cd backend && pytest -m unit` |
| api | `backend/tests/api` | все ручки через ASGI на настоящих Postgres и Redis, сценарии TC-02…TC-09 | `pytest -m api` |
| integration | `backend/tests/integration` | репозитории на Postgres и Redis | `pytest -m integration` |
| migrations | `backend/tests/migrations` | миграции вверх и вниз | `pytest -m migrations` |
| frontend (62) | `frontend/src/**/*.test.ts(x)` | права по ролям, форматирование, компоненты | `cd frontend && npm test` |

CI: [.github/workflows/backend-tests.yml](../../.github/workflows/backend-tests.yml) гоняет unit отдельно и остальное с сервисами Postgres и Redis.
