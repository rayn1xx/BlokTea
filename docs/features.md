# Функции продукта

Подробная роспись всех функций кабинета: что делает функция, кто ей пользуется, по каким правилам работает, где её найти в интерфейсе и API. Номера в скобках (Ф1-Ф35) ссылаются на таблицу [Бизнес_аналитика_фич.md](Бизнес_аналитика_фич.md), где для каждой функции указано, какую проблему клиентов или банка она закрывает.

Обозначения: **S…** — экраны клиента, **B…** — экраны банка ([frontend/routes.md](frontend/routes.md)). Ручки даны относительно `/api/v1`.

## 1. Вход, роли и команда

### 1.1. Вход по учётной записи Альфа-Бизнеса (Ф1)

- **Что делает.** Пользователь входит по почте и паролю. Роль в компании и права подтягиваются автоматически, отдельная регистрация не нужна.
- **Как работает.** `POST /auth/login` выдаёт короткий access-токен (JWT, 15 минут) и refresh-токен в HttpOnly cookie. Refresh-токен ротируется при каждом обновлении; если кто-то повторно использует старый токен, все сессии пользователя отзываются. Вход ограничен 10 попытками в минуту.
- **Куда ведёт после входа.** Сотрудник банка попадает в очередь заявок (B1). Клиент без пройденного онбординга — на экран данных компании (S3). Пользователь без роли в компании видит экран «Нет доступа к компании» с объяснением, к кому обратиться.
- **Где.** S1 «Старт», S2 «Вход»; `POST /auth/login`, `/auth/refresh`, `/auth/logout`.

### 1.2. Роли и права сотрудников компании (Ф24)

Шесть клиентских ролей из кейса. У каждой роли права по умолчанию, собственник может их менять для конкретного сотрудника.

| Роль | Подать заявку | Загружать документы | Подписывать | Принимать предложения | Управлять командой |
|---|:-:|:-:|:-:|:-:|:-:|
| Собственник (`owner`) | ✓ | ✓ | ✓ | ✓ | ✓ |
| Директор (`director`) | ✓ | ✓ | ✓ | ✓ | |
| Финансовый директор или бухгалтер (`cfo_or_accountant`) | | ✓ | ✓ | | |
| Сотрудник по финансированию (`financing_employee`) | ✓ | ✓ | | | |
| Сотрудник по банковским продуктам (`banking_employee`) | ✓ | ✓ | | | |
| Иной уполномоченный сотрудник (`authorized_employee`) | | ✓ | | | |

- Интерфейс показывает только доступные действия: каждая заявка отдаёт список `available_actions`, и кнопки строятся по нему.
- Бэкенд проверяет права ещё раз: без роли `403 NO_COMPANY_ROLE`, без права `403 FORBIDDEN_ACTION`, чужая заявка `404`.
- Главная зависит от роли: у бухгалтера своя версия, сфокусированная на документах и запросах банка.

### 1.3. Команда и приглашение сотрудников (Ф24)

- **Что делает.** Собственник видит всех сотрудников, их роли и права, приглашает новых, меняет права, отключает доступ.
- **Как работает.** Приглашение создаёт код (`4821-KX` в демо). Сотрудник входит по коду на экране S4, задаёт пароль и попадает в статус «Ждёт подтверждения». Собственник подтверждает, и сотрудник получает доступ.
- **Где.** S21 «Команда», S8 «Пригласить», S4 «По приглашению»; `/company/members/*`, `POST /auth/invite/accept`.

### 1.4. Правила подписи компании (Ф23)

- **Что делает.** Описывает, кто может отправлять заявку на подписание и кто в каком порядке подписывает документы.
- **Пример из демо.** В ООО «Машпромхоз» кредитный договор подписывает Смирнов, договор поручительства — Петров как второй собственник. У ИП Орловой одна подпись владельца.
- **Где.** S21; `GET/PUT /company/signing-rules`. Правила применяются при подписании (раздел 10).

## 2. Компания и финансы

### 2.1. Профиль компании из реестров (Ф2)

- **Что делает.** Реквизиты (ИНН, ОГРН, КПП, адрес, ОКВЭД, руководитель, категория МСП) заполняются сами из ЕГРЮЛ/ЕГРИП и реестра МСП. Клиент только подтверждает «Всё верно» или сообщает о несовпадении.
- **Онбординг.** S3: подтвердить реквизиты, дополнить профиль. Прогресс заполненности виден на главной, пока онбординг не завершён.
- **Где.** S3, профиль компании; `GET /company/profile`, `POST /company/registry/confirm`, `PATCH /company/details`, `POST /onboarding/complete`.

### 2.2. Деньги бизнеса из Альфа-Бизнеса (Ф9)

- **Что делает.** Показывает поступления, расходы и свободный денежный поток по месяцам за последние 12 полных месяцев, текущие кредиты и платежи по ним. Вводить ничего не нужно: данные берутся из операций по счетам.
- **Как считается.** Из оборотов исключаются переводы между своими счетами, поступления кредитов и платежи по кредитам, чтобы поток не завышался.
- **Уточнение.** Если клиент знает, что данные неполные (например, есть счета в других банках), он может их уточнить. Уточнения хранятся отдельно с автором и датой и учитываются в расчётах.
- **Где.** Шаг 2 подбора, профиль компании; `GET/PATCH /company/finance-summary`.

### 2.3. Готовность к кредиту (Ф12)

- **Что делает.** До подачи заявки показывает, как банк увидит компанию, по семи пунктам: срок работы бизнеса, долговая нагрузка, налоговая задолженность, кредитная история, документы, обороты по счёту, статус в реестре.
- **Как работает.** Каждый пункт получает статус «в порядке», «внимание», «проблема» или «нет данных», значение (например «нагрузка 24,1%»), объяснение, откуда данные, и подсказку, как улучшить, со ссылкой на действие (загрузить документ, дополнить данные).
- **Пороги.** Срок бизнеса: от 12 мес. в порядке, 6-11 внимание, меньше 6 проблема. Нагрузка: до целевой (26,5%) в порядке, до порога (30%) внимание, выше проблема. Налоговый долг до 10 000 ₽ — внимание, выше — проблема.
- **Где.** «Готовность к кредиту»; `GET /company/readiness`. С ИИ советы формулирует модель (задача И6), без ИИ — шаблоны.

### 2.4. Стресс-тест «Запас прочности» (Ф29)

- **Что делает.** Показывает, что будет с платежами, если выручка упадёт или расходы вырастут. Клиент двигает ползунки «Падение выручки» и «Изменение расходов».
- **Что видно.** Поступления и расходы в месяц, платежи по кредитам, сколько остаётся после платежей, покрываются ли платежи и на сколько месяцев хватит подушки. Если денег не хватает, система называет сумму, которую стоит держать в резерве.
- **Где.** Экран готовности, компонент `StressTest`. Расчёт на клиенте по данным `finance-summary`.

## 3. Главная и навигация по делам

### 3.1. Главная кабинета

- Приветствие, компания, счета с остатками, прогресс онбординга, счётчик непрочитанных уведомлений.
- Кнопки заявок по группам: черновики, в банке, ждут подписания, завершены. Счётчики приходят с бэкенда (`counters`).
- Блоки «Требуется ваше действие», персональное предложение, лента.
- **Где.** S5 (предприниматель), S6 (бухгалтер); `GET /home`, `GET /applications`.

### 3.2. «Требуется ваше действие» (Ф6)

- **Что делает.** Собирает в одном месте всё, что ждёт пользователя: ответить на запрос банка, принять предложение, подписать договор, дозагрузить документ.
- **Как работает.** Задачи создаёт система при событиях конвейера. У каждой задачи есть кнопка перехода (`cta`) и срок. Закрываются задачи тоже автоматически, когда действие выполнено.
- **Где.** Главная; `GET /tasks?scope=mine|all`.

### 3.3. Передать задачу коллеге (Ф25)

- **Что делает.** Собственник передаёт задачу сотруднику, у которого есть нужное право. Например, запрос отчётности уходит бухгалтеру.
- **Правила.** Нельзя передать неактивному сотруднику или сотруднику без нужного права: система объясняет, какого права не хватает. После передачи у заявки видно «Ждём: Малькина А. В. (бухгалтер)».
- **Также.** Можно передать черновик заявки целиком (`handoff`) или попросить коллегу загрузить документ (`POST /tasks/request-document`).
- **Где.** Модальное окно S7; `POST /tasks/{id}/reassign`, `POST /applications/{id}/handoff`.

### 3.4. Все заявки (Ф7)

- **Что делает.** Список заявок компании со статусом понятным языком, следующим шагом и тем, кого ждём.
- **Как работает.** Фильтр по статусам (вкладки «Ждут вас», «В банке», «Завершены»), сортировка по дате и сумме, пагинация.
- **Где.** Список заявок; `GET /applications`.

## 4. Подбор кредита и каталог

### 4.1. Подбор кредита по задаче за 4 шага (Ф8)

Клиенту не нужно разбираться в продуктах: он описывает задачу, система подбирает варианты.

| Шаг | Что вводит клиент | Что делает система |
|---|---|---|
| 1. Потребность (S9) | на что нужны деньги, сумма, срок, разовая или регулярная потребность, всей суммой или частями, насколько срочно, готовность к залогу | сохраняет ответы в сессии подбора |
| 2. Финансы (S10) | подтверждает «данные актуальны» или уточняет | показывает поступления, расходы и свободный поток из Альфа-Бизнеса |
| 3. Дополнительно (S11) | ожидаемые оплаты по договорам, счета в других банках, собственные средства на проект, возможный залог; шаг можно пропустить | учитывает сведения в расчёте |
| 4. Рекомендация (S12) | выбирает вариант | показывает до 3 вариантов |

- **Как подбирается вариант.** Для каждого подходящего продукта перебираются сроки (запрошенный и на 12 месяцев дольше) и суммы от запрошенной вниз с шагом 100 000 ₽. Берётся максимальная сумма, при которой долговая нагрузка не выше целевой (26,5%). Главная рекомендация — вариант с наибольшей суммой.
- **Если ничего не подошло** по ответам клиента, подбор смотрит все продукты, доступные по форме бизнеса, сроку работы и залогу.
- **Сессия сохраняется:** после перезагрузки страницы подбор продолжается с того же шага.
- **Где.** S9-S12; `/matching-sessions/*`.

### 4.2. Рекомендация с объяснением (Ф10)

- По каждому варианту: продукт, сумма, срок, ставка, ежемесячный платёж, переплата, нагрузка после кредита, насколько вариант подходит (`fit`).
- Блок «Почему именно этот вариант» объясняет выбор на числах клиента. С ИИ текст пишет модель (задача И4), числа сверяются с расчётом.
- Клиент может взять рекомендованные условия или оставить запрошенную сумму.
- **Где.** S12; `POST /matching-sessions/{id}/recommend`.

### 4.3. Предупреждение о сумме и нагрузке (Ф11)

- Если клиент оставляет сумму, при которой нагрузка выше целевой, система заранее предупреждает: с какой нагрузкой уйдёт заявка и чем это грозит (контрпредложение или отказ).
- Клиент подтверждает, что видел предупреждение (`client_warning_accepted`). Нагрузка на момент отправки фиксируется в заявке (`load_at_submit`), чтобы аналитик видел ту же цифру, что и клиент.

### 4.4. Каталог продуктов и калькулятор (Ф13)

Семь продуктов, условия взяты из публичных данных. Продукты, которых нет у банка в таком виде, помечены как демонстрационные.

| Продукт | Сумма | Срок | Ставка от | Залог | Бизнесу не меньше | Решение |
|---|---|---|---|---|---|---|
| Пополнение оборотных средств | 0,3-30 млн ₽ | 3-36 мес. | 15% | по желанию | 6 мес. | 1 рабочий день |
| Кредит на оборудование | 0,5-100 млн ₽ | 12-84 мес. | 14,5% | по желанию | 12 мес. | 2-3 рабочих дня |
| Овердрафт | 0,1-5 млн ₽ | 12 мес. | 17% | нет | 6 мес. | в день обращения |
| Кредитная линия | 1-150 млн ₽ | 12-36 мес. | 15,5% | по желанию | 12 мес. | 2-3 рабочих дня |
| Экспресс-кредит (демо) | 0,1-1 млн ₽ | 3-24 мес. | 19% | нет | 6 мес. | 15 минут |
| Кредит на любые цели | 0,3-10 млн ₽ | 6-36 мес. | 18% | нет | 12 мес. | 1 рабочий день |
| Льготная программа (демо, только ООО) | 1-50 млн ₽ | 12-60 мес. | 11% | обязателен | 12 мес. | до 5 рабочих дней |

- Карточка продукта: кому подходит и кому нет, требования, нужные документы, срок решения.
- Калькулятор считает аннуитетный платёж, переплату и сумму к возврату.
- **Где.** S13; `GET /products`, `GET /products/{code}`, `POST /calculator/payment`.

### 4.5. Персональное предложение (Ф3)

- **Что делает.** Показывает предодобренный лимит из Альфа-Бизнеса: сумма, ставка, платёж, залог, график и расходы, требования и документы.
- **Важно.** Под условиями стоит пометка «Окончательное решение после рассмотрения заявки», чтобы клиент не принял предложение за одобрение (такие жалобы есть в отзывах). Расчёты готовности и стресс-теста подписаны так же: «Это ориентир, а не решение банка». Из предложения можно сразу создать заявку.
- **Где.** Модальное окно на главной и в каталоге; `GET /offers/preapproved` (`204`, если предложения нет), `POST /applications` с `source = preapproved`.

## 5. Заявка

### 5.1. Создание заявки

Три источника: из рекомендации подбора, из каталога или из персонального предложения. Параметры (продукт, сумма, срок, цель) переносятся автоматически. Номер заявки выдаётся сразу: `КЗ-2026-001044`.

**Где.** `POST /applications`.

### 5.2. Автозаполнение и автосохранение (Ф14)

- Данные компании, руководителя и финансов подставляются из профиля и Альфа-Бизнеса. Клиент проверяет, а не вводит.
- Черновик сохраняется автоматически на каждом шаге. Если два сотрудника правят одну заявку, второй получает `409 VERSION_CONFLICT` вместо тихой перезаписи.
- **Где.** S14; `PATCH /applications/{id}`.

### 5.3. Чек-лист «Что нужно для отправки» (Ф18)

- Перечисляет всё, без чего заявку нельзя отправить: согласия, обязательные документы по продукту, подтверждения. У каждого пункта статус и кнопка действия: загрузить, выбрать из документов компании, взять из Альфа-Бизнеса.
- **Где.** S14, шаг «Проверка»; `GET /applications/{id}/requirements`.

### 5.4. Согласия с подписью кодом

- Согласие на запрос в бюро кредитных историй и другие согласия подписываются одноразовым кодом прямо в кабинете, без SMS.
- Код живёт ограниченное время, число попыток ограничено, ввод кодов ограничен 10 попытками в минуту. В демо (`DEMO_MODE=true`) код показывается рядом с полем.
- **Где.** `POST /applications/{id}/consents/{type}/challenge` → `.../confirm`.

### 5.5. Отправка в банк

- После отправки заявка становится объектом банковского процесса: статус «Отправлена», затем фоновые автопроверки (раздел 7).
- Повторная отправка той же заявки невозможна (`409`), повтор запроса с тем же `Idempotency-Key` возвращает сохранённый ответ.
- **Где.** `POST /applications/{id}/submit`.

### 5.6. Карточка заявки с таймлайном (Ф15)

- Текущий статус понятным языком, кого ждём, срок ответа, доступные действия.
- Таймлайн: все события заявки с датой, автором (клиент, банк, система) и описанием: создана, отправлена, проверка данных, запрос информации, решение, подписание, выдача.
- Вкладки: параметры, документы, решение, звонки с менеджером.
- **Где.** S15; `GET /applications/{id}`.

### 5.7. Отзыв заявки

- Клиент может отозвать заявку на любом этапе до выдачи, с причиной. Выданную, отклонённую и уже отозванную заявку отозвать нельзя.
- **Где.** `POST /applications/{id}/cancel`.

### 5.8. Карточки звонков (Ф28)

- Итоги каждого разговора с аналитиком видны клиенту в карточке заявки: тема, краткое содержание, договорённости, следующий шаг и срок.
- Закрывает жалобы вида «менеджер сказал одно, а сделали другое».
- **Где.** Вкладка заявки; аналитик создаёт через `POST /bank/applications/{id}/calls`.

## 6. Документы

### 6.1. Документы компании загружаются один раз (Ф17)

- Документы хранятся на уровне компании (устав, решение о назначении директора, отчётность, выписки) и переиспользуются во всех заявках. Документы конкретной заявки хранятся отдельно.
- **Справочник типов.** Устав; решение о назначении директора; паспорт предпринимателя; бухгалтерская отчётность за 2025 год; налоговая декларация за 2025 год; выписка из другого банка за 6 месяцев; выписка по счёту в Альфа-Банке; справка об оборотах; документы по залогу; патент ПСН; другой документ.
- **Версии.** Новый файл того же документа загружается как новая версия, номер версии виден в карточке.
- **Где.** S20; `/documents/*`.

### 6.2. «Нужно добавить» (Ф18)

- Показывает, каких документов не хватает компании и для каких заявок, с причиной.
- **Где.** S20, главная; `GET /documents/missing`.

### 6.3. Документы из Альфа-Бизнеса без загрузки

- Выписку по счёту, налоговые данные и справку об оборотах клиент получает одним нажатием за выбранный период: система запрашивает их в Альфа-Бизнесе и сохраняет как готовый PDF.
- Если Альфа-Бизнес недоступен, клиент видит понятную ошибку и предложение загрузить файл вручную.
- **Где.** `POST /documents/from-lk`.

### 6.4. Загрузка файлов

- PDF, JPG, PNG, XLSX, TXT, XML. Лимит размера зависит от типа документа: 10-30 МБ. Формат определяется по содержимому файла, а не по расширению (исполняемый файл с расширением `.pdf` не пройдёт), имя файла очищается от путей.
- При включённом ИИ после загрузки начинается фоновая проверка (6.5).
- **Где.** `POST /documents` (multipart), `POST /documents/{id}/versions`.

### 6.5. ИИ-проверка документа (Ф19)

- **Что делает.** Определяет тип документа, извлекает поля (ИНН, организация, дата, период, выручка или обороты) и проверяет документ на соответствие запросу.
- **Проверки делает код, а не модель:**
  - тип совпадает с запрошенным;
  - ИНН совпадает с ИНН компании;
  - документ не старше допустимого срока;
  - период документа корректен и достаточно свежий.
- **Итог.** По каждой непройденной проверке понятное замечание: что не так и что сделать (текст пишет модель, задача И3, или шаблон). Если модель не уверена в типе или поле, поле не используется.
- **Чтение файлов.** PDF — текстовый слой первых 5 страниц; PNG и JPG — мультимодальная модель (И2), при её отсутствии Tesseract OCR. Паспорт в модель не отправляется.
- **Где.** Карточка документа; фоновая задача после загрузки, `POST /documents/{id}/analyze` для повторной проверки.

## 7. Автопроверки, скоринг и авторешение

Срабатывает автоматически после отправки заявки, в фоне. Клиент видит смену статуса через несколько секунд.

### 7.1. Обогащение данных из внешних источников

| Проверка | Источник (мок) | Результат |
|---|---|---|
| Реестр | ЕГРЮЛ / ЕГРИП | компания действует; ликвидация — стоп-фактор |
| Кредитная история | БКИ | без просрочек / просрочки до 30 дней за 12 мес. (предупреждение) / текущая просрочка (стоп-фактор) |
| Обороты | Альфа-Бизнес | стабильны / сезонный спад (не предупреждение) / месяцы без поступлений или история меньше 6 месяцев (предупреждение) |
| Налоги | ФНС «Прозрачный бизнес» | долг больше 10 000 ₽ — стоп-фактор |
| Нагрузка | расчёт | выше порога — проблема; расходы не меньше поступлений — стоп-фактор |

Каждая проверка хранится с итогом, деталями и сырым ответом источника. Если источник не ответил, проверка получает статус «ошибка», и заявка уходит аналитику вместо авторешения. Аналитик может повторить проверки.

### 7.2. Долговая нагрузка

`(платёж по новому кредиту + текущие платежи) / свободный денежный поток × 100`. Платёж аннуитетный, по овердрафту в нагрузку идут только проценты на лимит. Порог 30%, целевая нагрузка 26,5%. Подробно: [scoring-decision.md](scoring-decision.md).

### 7.3. Скоринг

Балльная модель на 100 баллов:

| Фактор | Максимум |
|---|---|
| Срок работы бизнеса | 20 |
| Кредитная история | 20 |
| Долговая нагрузка | 25 |
| Отрасль (по ОКВЭД) | 15 |
| Стабильность оборотов | 20 |

Пороги: от 70 — одобрение, 55-69 — другие условия, 45-54 — ручная проверка, ниже 45 — отказ.

### 7.4. Авторешение

1. Источник не ответил → в очередь аналитика.
2. Не хватает обязательного документа → система сама создаёт запрос информации со сроком 5 дней.
3. Стоп-фактор или балл ниже 45 → отказ с объяснением.
4. Балл от 70 и нет предупреждений → одобрение без участия аналитика.
5. Иначе → в очередь аналитика с рекомендацией.

## 8. Рабочее место аналитика

### 8.1. Очередь заявок с приоритетом (Ф30)

- Заявки в банке и автоматически решённые (для контроля). Автоматически решённые идут в конце.
- По каждой заявке: компания, сумма, балл, уровень риска, итог проверок и подсказка, сколько минут ждёт, кто взял в работу.
- Фильтры: «мои», «высокий риск», «есть стоп-факторы». Сортировка по времени ожидания или по риску.
- **Где.** B1; `GET /bank/applications`, `POST /bank/applications/{id}/take`.

### 8.2. Карточка заявки для аналитика (Ф31)

- Параметры заявки и нагрузка на момент отправки, результаты всех проверок с деталями, скоринг по факторам с объяснением, документы с итогами ИИ-проверки, история звонков, таймлайн.
- Повтор проверок, если источник был недоступен.
- **Где.** B2; `GET /bank/applications/{id}`, `POST .../rerun-checks`.

### 8.3. ИИ-резюме заявки (Ф32)

- Короткое резюме для аналитика: сильные стороны, риски, на что обратить внимание. Все числа в резюме сверяются с данными заявки. Название компании в модель не передаётся (у ИП это ФИО).
- **Где.** B2; `POST /bank/applications/{id}/ai-summary` (задача И7).

### 8.4. Решение в один экран (Ф33)

Четыре варианта решения:

| Решение | Что указывает аналитик | Что получает клиент |
|---|---|---|
| Одобрить | — | условия и кнопку «Принять» |
| Другие условия | сумма, срок, ставка, продукт, причина; система предлагает до 3 готовых вариантов | «вы просили / банк предлагает» |
| Запросить данные | шаблон или свой вопрос, типы документов, срок | задачу и экран запроса |
| Отказать | причины из справочника | объяснение без слова «отказано» и советы |

- **Предпросмотр.** Перед отправкой аналитик видит текст, который получит клиент.
- **Варианты контрпредложения** система подбирает так, чтобы нагрузка была не выше целевой, а балл — от 70.
- **Справочники.** Шаблоны запросов: отчётность за 2025 год, выписка из другого банка, справка об оборотах, документы по залогу. Причины отказа: высокая нагрузка, недостаточные обороты, кредитная история, налоговая задолженность, срок работы бизнеса, документы не подтверждают заявку, другая.
- **Где.** B3; `GET .../counter-offer-options`, `POST .../decision/preview`, `POST .../decision`.

### 8.5. Показатели процесса (Ф34)

- Сколько заявок на рассмотрении, среднее время до решения, доля авторешений, доля запросов данных, распределение заявок по статусам за период.
- **Где.** B4; `GET /bank/dashboard`.

### 8.6. Настройки скоринга (Ф35)

- Администратор банка меняет пороги «автоодобрение от», «другие условия от», «ручное рассмотрение от», порог и целевую нагрузку. Изменения применяются сразу, без перезапуска, ко всем следующим расчётам.
- **Где.** B4; `GET/PUT /bank/settings/scoring` (только `bank_admin`).

## 9. Решение банка для клиента

### 9.1. Решение с объяснением (Ф20)

- Понятный текст: что решил банк и почему, на конкретных цифрах клиента. С ИИ текст пишет модель (задачи И5, И8), без — шаблоны; числа подставляет код.
- Видно, кто принял решение: автоматически или аналитик.

### 9.2. «Вы просили / банк предлагает» (Ф21)

- При контрпредложении две колонки: запрошенные и предложенные сумма, срок, ставка, платёж. Объяснение, почему условия другие, и платёж по новым условиям.
- Клиент принимает (заявка переходит к подписанию) или отказывается с причиной (заявка завершается).
- **Где.** S17; `POST /applications/{id}/offer/accept`, `.../offer/decline`. Принять может только сотрудник с правом `accept_offers`.

### 9.3. Диагностика после отказа (Ф22)

- Причины отказа человеческим языком и конкретные советы, что улучшить перед следующей заявкой: снизить сумму, увеличить срок, погасить налоговый долг, подождать срок работы бизнеса и т. п.
- Ссылка на экран готовности, чтобы отслеживать прогресс.

### 9.4. Запрос банка внутри кабинета (Ф16)

- Вопрос аналитика, нужные документы, срок ответа, кнопки «загрузить», «выбрать из документов компании», «взять из Альфа-Бизнеса». Ответ можно дать документами, комментарием или тем и другим.
- Когда клиент ответил на все открытые запросы, заявка автоматически возвращается на рассмотрение.
- **Где.** S16; `GET/POST /applications/{id}/info-requests/{rid}[/respond]`.

## 10. Подписание и выдача

### 10.1. Подписание по правилам компании (Ф23)

- После принятия условий создаётся очередь подписантов по правилам компании: какой документ, кто подписывает, в каком порядке.
- Каждый подписывает своим кодом в кабинете. Подписать раньше своей очереди нельзя.
- Экран показывает, кто уже подписал, а кого ждём. Можно напомнить коллеге: ему придёт уведомление в кабинет.
- **Где.** S18; `GET /applications/{id}/signing`, `POST .../signing/challenge` → `.../confirm`, `POST .../signing/remind`.

### 10.2. Выдача и график платежей (Ф26)

- После последней подписи заявка получает статус «Кредит выдан». Создаётся кредит: сумма, ставка, срок, счёт зачисления и график платежей по месяцам с разбивкой на основной долг и проценты. Выдача смоделирована без движения денег.
- **Где.** S19; `GET /loans`, `GET /loans/{id}`.

### 10.3. История платежей (Ф27)

- Гистограмма платежей по месяцам: сколько ушло на основной долг и сколько на проценты, прошлые и будущие платежи. Так видно, почему платёж изменился.
- **Где.** S19, компонент `PaymentsHistory`.

## 11. Лента и уведомления

### 11.1. Персональная лента «Для вашей компании» (Ф4)

- **Что делает.** Новости, программы господдержки, советы и обновления продуктов, отобранные под конкретную компанию, а также последние события по её заявкам.
- **Как отбирается.** У каждой новости есть правила показа (`targeting`):
  - форма бизнеса (ООО или ИП);
  - префиксы ОКВЭД (отрасль);
  - сезонный спад поступлений;
  - пункты готовности со статусом «внимание»;
  - продукт.
- **Причина показа.** У каждой новости строка «Показано, потому что: …», например «вы ИП, документы для ИП отличаются от ООО».
- **Пример.** ООО «Машпромхоз» (металлообработка) видит льготные кредиты для обрабатывающих производств, цены на металлопрокат и совет о спаде в январе-феврале. ИП Орлова (пекарня) — поддержку общепита в Московской области и документы для ИП на патенте.
- **Действия.** У новости может быть кнопка: посмотреть продукт, подобрать кредит, загрузить документ.
- **Где.** Главная и экран ленты; `GET /feed`.

### 11.2. Уведомления в кабинете (Ф5)

- О смене статуса заявки, решении банка, запросе информации, необходимости подписать, напоминании коллеги. Только внутри продукта, без почты и SMS.
- Счётчик непрочитанных на главной, панель уведомлений, «прочитать всё». Уведомление ведёт прямо на нужный экран.
- **Где.** Панель уведомлений; `GET /notifications`, `POST /notifications/{id}/read`, `POST /notifications/read-all`.

## 12. ИИ-функции

Модель с открытыми весами (Qwen3.5 9B) работает локально через Ollama и включается флагом `LLM_ENABLED=true`. Кредитное решение, баллы и суммы всегда считает код.

| Задача | Что делает | Где |
|---|---|---|
| И1 | тип документа и поля из текста | загрузка документа |
| И2 | то же для сканов и фото (мультимодальная модель) | загрузка PNG/JPG |
| И3 | замечания по непройденным проверкам документа | карточка документа |
| И4 | объяснение рекомендации подбора | S12 |
| И5, И8 | объяснение решения и советы после отказа | решение (авто и аналитика) |
| И6 | советы по готовности к кредиту | экран готовности |
| И7 | резюме заявки для аналитика | B2 |

**Защита от ошибок модели:**
- ответ строго в JSON по схеме, одна повторная попытка;
- все числа в тексте сверяются со входом: модель не может «придумать» сумму или ставку;
- при сбое, таймауте или расхождении используется шаблон (`text_source = template`), процесс не останавливается;
- в модель не уходят ФИО, паспорта и номера счетов.

Подробно и с замерами скорости: [llm.md](llm.md).

## 13. Сквозные механизмы

| Механизм | Что даёт |
|---|---|
| Машина состояний заявки | только допустимые переходы, `409 INVALID_TRANSITION` на остальные ([diagrams/application-states.md](diagrams/application-states.md)) |
| Журнал событий и аудит | каждое действие клиента, банка и системы с автором и временем |
| Оптимистичная блокировка | одновременная правка черновика не теряет данные |
| Идемпотентность `POST` | повтор запроса (двойной клик, сбой сети) не создаёт дубль |
| Rate limit | защита входа и кодов подтверждения от перебора |
| Деградация при сбоях | недоступный источник или модель не ломают сценарий |
| Моки внешних систем | автономная работа без доступа к системам банка; `MOCKS_DOWN` для проверки сбоев |
| Демо-режим | коды подтверждения в интерфейсе, демо-данные и сброс `make reset-demo` |
